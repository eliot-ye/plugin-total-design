# YAGNI 阶梯

> 本文件与同目录的 `brooks-law.md` / `critical-buffer.md` / `delay-decision.md` / `human-in-loop.md` / `wip-limit.md` 是平级兄弟文件，正文中出现的裸逻辑名均指同目录对应变体文件；裸逻辑名 `yagni-ladder` 指本文件。

## 服务的主基调原则

**系统工程主基调第 1 条：系统工程。** 局部动作从整体性能反推——写代码前先看系统里已有什么，而不是从零造。过度工程是典型的局部优化：为"可能用到"的灵活性增加全局复杂度，制造失调。

**系统工程主基调第 4 条：层次观。** 能复用既有层就不新建层，能用平台原生特性就不自研组件——尊重系统既有的层次结构。

「对解法懒，对改动本身绝不懒」：本文件约束的是**解法的重量**，不是执行的完整性——该做的部分（调用方适配、测试、fixture）一个都不能少。

## 规则

### 六级决策阶梯（写代码前按序找第一个"完全能用"的）

写任何新代码前，从第 1 级往下找，**命中即停**，不为更高目标继续往下：

| 级 | 判据 | 动作 |
|---|---|---|
| **1 需要存在吗** | 没人要求的功能 / 灵活性 / "以后可能用" | 直接跳过，并用一行点名跳过了什么 |
| **2 代码库里已有** | 已有 helper / component / service / 既定模式 | 照周围代码的用法复用 |
| **3 标准库或平台原生** | 语言标准库 / 框架原生特性 / 浏览器原生 widget | 用它（自研组件让位于原生） |
| **4 已安装的依赖** | 项目已依赖的库能做 | 用它。**绝不"为几行代码加一个依赖"** |
| **5 能写成一行** | 一行、读者一眼看懂 | 一行 |
| **6 最小实现** | 以上都不命中 | 能工作的最小代码 |

**"完全能用"的判据**：满足当前 change 的契约（spec / tasks 验证字段），不含未被要求的额外能力。第 6 级是兜底不是默认——多数改动应在 2–4 级命中。

### never-cut 负向清单（"懒"的红线）

阶梯鼓励对解法懒，但以下**永不裁剪**——它们是"懒"不可逾越的边界，越界即从"反过度工程"退化为"偷工"：

- 信任边界处的输入校验
- 防数据丢失的错误处理
- 安全（鉴权 / 授权 / 凭证处理）
- 可访问性
- 用户显式要求的任何东西

命中红线的能力即使当前测试没覆盖，也按 full 强度做，不走阶梯降级。

### `shortcut:` 捷径标注（技术债物化）

走捷径（降级实现 / 留已知上限的简化 / 暂时绕过某能力）时，在该代码处留一行标注：

```
# shortcut: <走了什么捷径>, <何时升级>
例：# shortcut: 串行扫描，接入方超过 3 个时改索引
```

与同目录 `delay-decision.md` 的 `td-cut:` 砍角标注分工：`td-cut:` 标"故意砍角"（有真实 ceiling 的降级），`shortcut:` 标"走了阶梯之外的重路"（本该在第 2–4 级命中却写了第 6 级的自研）。两者都是代码侧锚点，让债务在 diff 里可见，`td-archive` 收尾时核对收敛。

## 触发时机（信号驱动，不是每次写代码都过）

阶梯是判断工具，不是实施默认仪式——**命中下列信号才查，不命中不凑**：

- agent 准备"装一个新依赖"或"新建一个 helper / 组件 / 抽象"时
- agent 写出超过任务验证字段所需能力的代码时（顺手加的配置项、防御性分支、提前抽象）
- 用户说"别过度设计""先简单做""YAGNI"时

普通实施（复用既有模式的小改动）不要求逐次过阶梯——阶梯默认对齐 `td-apply` 步骤 4 的"实现默认对齐既有代码风格与既有实现模式"。是否触发由 `td-apply` 步骤 4 的信号判据承载。

## 触发时 agent 应做的事

1. 对即将写的代码，从阶梯第 1 级往下判，说出命中的级别与依据（"第 2 级：仓库已有 `Input` 组件"）
2. 命中 1–4 级 → 复用，不新写；命中 6 级 → 写最小实现
3. 检查是否触碰 never-cut 清单——触碰则按 full 强度做，不走降级
4. 走了阶梯之外的重路 → 留 `shortcut:` 标注

## 不做的事

- 不为"以后可能用"写灵活性——YAGNI
- 不为几行代码引入新依赖
- 不把 never-cut 清单里的东西当"可懒"项裁掉
- 不用 `shortcut:` 标注掩盖该做的完整改动（标注是债务记账，不是免做令牌）

## 与其他 skill 的关系

- 与 `delay-decision` 配合：`delay-decision` 管"决策何时闭合"，本文件管"实现用多重解法"——一个可逆决策在延迟期内先用最简方案往前走，落到的"最简"具体怎么判，走本文件的阶梯
- 与 `td-cut:`（`delay-decision.md`）配合：两者都是代码侧债务锚点，`td-cut:` 标砍角、`shortcut:` 标走重路，`td-archive` 一并核对
- 与 `test-driven-development` 配合：测试的"何时写、写多重"由该 skill 独立管辖（RED-GREEN-REFACTOR）；本文件只约束**解法的重量**，不另设测试要求——第 6 级最小实现该不该配测试、配多重，走该 skill 的判据
