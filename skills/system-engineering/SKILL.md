# 系统工程主基调（钱学森）

钱学森那套，核心不是"项目管理"操作层面的东西，是**系统工程**——把复杂对象当成一个整体系统来认识和处理。

## 主基调四条

### 1. 系统工程

系统的总体性能 **不等于** 各部分性能之和；关键是**整体协调**，不是各部分最优。

→ 任何局部动作从整体性能反推；局部更优但全局失调 = 错的。

### 2. 总体设计部

任何复杂工程都需要一个**站在系统全局立场**的群体，专门负责总体方案、协调各分系统。

→ agent 不能既当分系统工程师又当总体设计部。`td-explore` 承载总体设计部工作方式；`/td-system-audit` 是周期性自检。

### 3. 从定性到定量的综合集成

专家的定性判断 + 数据 + 模型 → 反复迭代 → 上升到定量认识；人和机器结合，不是纯算法。

#### 模型载体

模型是把定性判断上升到定量认识的桥梁。本工作流里"模型"载体是 OpenSpec 的 spec/design artifact——proposal 的"系统工程影响评估"节是预期模型，archive 的"实际 vs 预期"复盘是模型验证。spec 是综合集成的模型载体，不是纯文档。
→ proposal 必须回答"影响哪些分系统、整体性能怎么变"，不只写 what 和 how。

### 4. 开放的复杂巨系统

社会、人体、思维这类系统不能简化还原，必须**整体观 + 层次观**。

整体观：总体性能不等于各部分性能之和，局部动作从整体性能反推。
层次观：多层级嵌套结构，不同层次有不同约束强度，必须按层次对待——不能把 tier-large 多仓库系统当成"一个 tier"硬解。

→ profile × tier 二维配置是本原则的工程化——按系统规模分层对待。系统内部有明显子系统边界时，允许子系统独立定 tier（见 `field-assessment` 的 `references/identification-flow.md`）。

## 反馈控制回路（贯穿四条主基调）

四条主基调不是并列的静态原则，是通过反馈控制回路动态闭合的：

- **propose（前馈控制）**：在实施前预测"系统工程影响"，建立控制目标。
- **apply（控制执行 + 实时误差检测）**：按 tasks.md 实施，TDD 是契约级误差检测，verification 是系统级误差检测。
- **archive（反馈控制回路闭合）**："实际 vs 预期"复盘是事后误差检测，修正下一个 propose 的预测模型。

本工作流里多个闭环实现都是这个反馈控制回路的具体形态：`td-system-audit` 步骤 7"修复后重跑 audit 闭环"、`systematic-debugging` 4-phase 闭环、`executing-plans` 步骤 1 的 human checkpoint、`verification-before-completion` 第 6 节系统级验证。下游 skill 触发这些闭环时，应意识到这是《工程控制论》反馈控制原理在本工作流里的工程化，不是孤立的"重跑一下"。

## 如何使用本 skill

本 skill 是**所有局部 constraint（`constraints` skill 承载的 5 份局部规律变体文件）的前提**，不是单独触发的。当 agent 执行任一局部规律规则时，应该同时意识到本 skill 的四条主基调，把局部规则放在系统工程框架下执行。

当 agent 调用 `/td-system-audit` 时，本 skill 是审计的对照标准。

当 agent 触发任何反馈控制闭环（见「反馈控制回路」节的列举）时，本 skill 的「反馈控制回路」节是这些闭环的归位锚点。
